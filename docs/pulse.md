# Pulse — startup command center

Pulse is a first-class workspace view (sidebar → Pulse, or ⌘5). It uses the existing
Dots, Google identity, encrypted shared service, central agent and conversation.
It introduces no alternate integration credentials or analytics application.

## Current implementation

- Authorized source overview, cached evidence, freshness/status, 24H/7D/30D/90D/12M
  windows, native observed-activity charts, source-backed recent changes and drill-downs.
- Per-account/workspace pinning and ordering. Preferences contain metric IDs only.
- Investigate invokes the existing central read-only reasoning path in conversation.
  Discuss prepares an editable message; Build prepares an explicit build request.
  Neither sends a shared message nor starts coding without the user's next action.
- Read-only GitHub commits, open PRs in the returned issue sample, deployment records.
  Deployment records are not proof of successful deployment or production health.
- Dots credentials and workspace membership are checked for both cached and live reads.
  Changing users/workspaces/permissions clears the native page and open drill-down.
- One source can refresh independently. Opening Pulse never queries external providers.
  A minute-long visibility-gated status check refreshes only cached service metadata.
- Agent selection still chooses at most three relevant tools; it does not ingest Pulse
  or all sources on every chat message. Agent and overview cite the same evidence IDs.

GitHub API tools currently return the latest ten records. Counts are **observed sample
counts**, not repository totals. Open PRs describe the current sample, independent of
window. Missing/unparseable dates are excluded from time-window counts. There is no
complete comparison history, so percentage growth and previous-period comparisons
are withheld. Activity charts show sampled observations only; gaps are not proof of
inactivity. No causal inference or fabricated AI commentary is generated by Pulse.

Stripe, Supabase, Vercel, PostHog and Linear are planned providers, with no production
analytics tools yet. Revenue, MRR, signups, retention and anomalies will appear only
when a real adapter supplies authorized data with supported history. They are not
advertised as implemented. The new provider registry entry for Linear is unavailable;
its provider authentication and workspace-identity migration belong to its adapter task.

## Extension contract

Server `aedrova_site/dots.py` owns providers, authentication, tool authorization and
credential revocation. `aedrova_site/pulse.py` registers bounded overview tools and
provider projections. Every projection returns source/citation, fetched timestamp,
coverage, category, metric identity/value/unit, supported period, comparison coverage,
items and optional trend. Desktop rendering is category-driven, not provider-specific.

Cache entries are encrypted and keyed by Dot, user, workspace, version, tool and grant
fingerprint. Normal tool reads reuse evidence for up to five minutes; explicit source
refresh bypasses that cache. Expired grants, identity changes or reauthorization prevent
cache reuse. Evidence expires within 24 hours and never outlives the grant. Signed
GitHub events invalidate freshness through the existing Dot synchronization marker.
Disconnect/removal purge cached evidence. Derived data remains scoped to its authorizer.

Add each remaining provider with its official authorization, bounded normalized tools,
comparison-history contract and privacy/security tests; then register its projection.
Do not give models SQL, arbitrary URLs, service-role keys or unrestricted mutation tools.
Anomaly rules must depend on adequate real comparison history. Shared insights/task
creation and approved fix workflows can extend the existing evidence/decision/queue
infrastructure rather than silently changing publication permissions.
